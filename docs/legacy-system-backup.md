# 旧系统备份文档

## 概述

本文档记录了在升级到Mastra记忆系统之前的旧系统组件，作为历史参考和回滚备份。

## 已移除的组件

### 1. 自定义数据库结构
- **文件**: `src/database/migrations/001_initial_schema.sql`
- **描述**: 包含自定义的用户、产品、记忆表结构
- **替代方案**: Mastra原生记忆系统使用PostgreSQL存储

### 2. 自定义数据库Schema
- **文件**: `src/database/schema.ts`
- **描述**: TypeScript类型定义和Zod验证Schema
- **替代方案**: Mastra框架内置的记忆数据模型

### 3. 数据库连接管理
- **文件**: `src/database/connection.ts`
- **描述**: 复杂的多数据库连接管理（PostgreSQL + Redis + Pinecone）
- **替代方案**: Mastra简化的PostgreSQL连接配置

### 4. 数据库迁移系统
- **文件**: `src/database/migrator.ts`
- **描述**: 自定义的数据库迁移管理系统
- **替代方案**: Mastra自动处理数据库结构

### 5. 复杂工作流
- **文件**: `src/mastra/workflows/memory-workflow.ts`
- **描述**: 多步骤的记忆管理工作流
- **替代方案**: Mastra代理内置的记忆功能

## 迁移优势

### 简化架构
- 从复杂的多组件系统简化为Mastra统一框架
- 减少了维护负担和潜在故障点
- 提高了系统可靠性

### 性能提升
- Mastra优化的记忆管理算法
- 更高效的向量存储和检索
- 自动的记忆整合和清理

### 开发效率
- 减少了自定义代码量
- 利用Mastra的最佳实践
- 更好的TypeScript支持

## 保留的功能

### 代理系统
- 推荐代理 (`recommendationAgent`)
- 家电代理 (`applianceAgent`)
- 保持了原有的业务逻辑

### API接口
- 保持了相同的API端点结构
- 兼容现有的前端集成
- 流式响应功能

### 模型配置
- 继续使用火山引擎模型
- 保持了API密钥配置方式
- 支持模型切换

## 回滚计划

如果需要回滚到旧系统，可以：

1. 恢复 `src/database/` 目录下的所有文件
2. 重新配置多数据库连接
3. 运行数据库迁移脚本
4. 更新代理配置以使用旧的记忆系统
5. 恢复复杂的工作流定义

## 数据迁移记录

- Mastra记忆系统提供更好的语义理解

### 配置数据
- 环境变量配置已简化
- API密钥配置保持兼容
